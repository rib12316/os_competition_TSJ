# F2 LongLLMLingua tau-bench 10-task 串行测试

> 日期：2026-07-29
> 范围：tau-bench `retail/test`，`task_id=0..9`
> 顺序：先 baseline，再 F2；单并发；每组每任务运行 1 次

## 1. 实验配置

- Agent 模型：本地 vLLM `Qwen2.5-7B-Instruct`，地址 `http://127.0.0.1:8000/v1`
- USER 模型：`mimo-v2.5-pro`
- `seed=42`，`max_steps=20`
- baseline：不启用上下文压缩中间件
- F2 方法：`longllmlingua`，CPU `gpt2` 子进程压缩器，worker 数量 1
- F2 动态参数：`trigger_tokens=3000`、`rate=0.60`、`recompress_delta_tokens=2000`
- F2 其他参数：`keep_hot=6`、`tool_aware=false`、`hot_tool_trigger_tokens=0`
- F2 静态优化：`retail_compact` 系统提示词精简与工具描述去重均开启
- 运行环境显式移除了代理变量；两组 20 个任务全部首轮完成，无网络或运行时错误

## 4. 压缩收益与代价

F2 自身轨迹记录了 171 次模型调用：

| F2 内部配对口径 | token |
|---|---:|
| 变换前 Prompt | 1,233,075 |
| 变换后 Prompt | 924,591 |
| 节省 | 308,484（25.02%） |

- 事件分布：`compress=10`、`reuse=36`、`skip=125`
- 触发动态压缩的 session：6/10（task 0、1、3、4、7、8）
- 压缩器累计耗时：201.95 s，平均每次压缩约 20.2 s
- 单次动态压缩比约 1.7x 到 3.1x

25.02% 是 F2 同一模型调用内“原始 Prompt 与变换后 Prompt”的严格配对节省，包含静态系统/工具提示词优化和动态冷历史压缩的共同作用。baseline 共 173 次调用，F2 共 171 次调用，且各任务对话步数不同，因此不能把两组 Prompt 总量之差直接归因于 F2。

## 5. 结论

1. 本轮 F2 与 baseline 均通过 1/10，总体通过率没有下降，但样本仅 10 个且成功任务不同，不能据此声明质量等价。
2. F2 的上下文变换机制已有效工作：同轨迹配对 Prompt token 减少 25.02%，6/10 个任务触发动态压缩，复用机制避免了每一步重复压缩。
3. 当前 CPU `gpt2` LongLLMLingua 压缩器仍是主要工程代价。10 次压缩累计约 202 秒，与 p50 上升 13.0%、p95 上升 62.0% 的结果一致，但由于两组对话轨迹不同，不能把全部延迟差都归因于压缩器。
4. 该配置适合继续验证 token/上下文容量收益，不适合作为低延迟最终配置。后续性能测试应优先比较更快压缩器，或将压缩异步化/并行化。
